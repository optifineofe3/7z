Ты — senior iOS/C++ разработчик. Задача: сделать полноценный порт 7-Zip на iOS (приложение для сайдлоада через LiveContainer без джейлбрейка и без платного аккаунта разработчика). Исходники официального 7-Zip лежат в репозитории (7zip-ios, изучи структуру: C/, CPP/7zip/UI/Console, CPP/7zip/UI/Common, CPP/7zip/Bundles/Alone2, CPP/7zip/UI/Client7z, CPP/Windows, CPP/Common, makefile.gcc). Сборка и выпуск IPA — только через GitHub Actions.

== 1. ЦЕЛЬ ==
Приложение «7Zip» (SwiftUI + C++ ядро), которое по возможностям максимально близко к десктопному 7-Zip: открытие, просмотр, распаковка, тестирование, создание и обновление архивов со всеми основными параметрами. Ядро — оригинальный код 7-Zip, не libarchive и не самописные реализации. Минимальная iOS — 15.0, только arm64.

== 2. ЯДРО (C/C++) ==
2.1. Собрать статическую библиотеку из исходников 7-Zip под iOS arm64 (clang, Xcode). Ориентир по списку файлов и флагам — Linux-сборка (CPP/7zip/Bundles/Alone2/makefile.gcc и соседние .mak), не Windows-ветка. Выключить ассемблерные оптимизации, если они мешают iOS-сборке, и использовать C-реализации. Убедиться, что включены: 7z, zip, tar, gz, bz2, xz, wim, а для чтения ещё rar/rar5, iso, dmg, cab, arj, lzh, cpio, rpm, deb, vhd, squashfs и прочее, что собирается в Alone2. Кодеки: LZMA, LZMA2, PPMd, BZip2, Deflate/Deflate64, Copy, фильтры BCJ/BCJ2/ARM64/Delta, AES-256 (7zAES и ZipCrypto/AES для zip). Запретить внешние кодеки/DLL.
2.2. ЯДРО НЕЛЬЗЯ ЗАПУСКАТЬ КАК ОТДЕЛЬНЫЙ ПРОЦЕСС (на iOS нет fork/exec). Нужно вызывать в процессе приложения. Реализуй C-обёртку (extern "C", заголовок для Swift через bridging header или module map):
  - int sz_run(int argc, const char* const* argv, sz_callbacks* cb) — запуск команды в стиле 7zz (a, x, e, l, t, d, u, h, b, i), на базе Main2 из UI/Console;
  - sz_cancel() — корректная отмена (выставить break-флаг через механизм ConsoleClose / CtrlBreak или прерывать из колбэков с E_ABORT);
  - колбэки: прогресс (обработано/всего байт, текущий файл, скорость, оставшееся время), ошибки/предупреждения, запрос пароля, подтверждение перезаписи, завершение с кодом возврата.
  Рекомендуемый путь: сначала реализовать через Console-код (быстро получить рабочий результат), перехватывая вывод и подменяя печать прогресса (CPercentPrinter / UpdateCallbackConsole / ExtractCallbackConsole) на вызовы колбэков. Если это упирается в глобальное состояние, перейти на прямое использование UI/Common (Extract, Update, ArchiveCommandLine, IExtractCallbackUI, IUpdateCallbackUI, IOpenCallbackUI) по образцу Client7z. Интерфейс обёртки для Swift при этом не должен меняться.
2.3. Обязательные доработки кода:
  - убрать/заменить все exit() и abort() на возврат кода ошибки или исключение, пойманное в обёртке (ошибка в архиве не должна убивать приложение);
  - сбрасывать статическое/глобальное состояние между запусками (либо исполнять каждую операцию в чистом контексте), чтобы можно было запускать операции много раз подряд;
  - запуск операции в отдельном потоке с большим стеком (минимум 8 МБ), не в главном потоке;
  - гарантированная UTF-8 кодировка имён файлов (кириллица, эмодзи, CJK), setlocale/ForceToUTF8 как в Linux-ветке, проверить на архивах с русскими именами;
  - никаких обращений к stdin; пароли только через колбэк;
  - код ошибок 7-Zip (0,1,2,7,8,255) возвращать в Swift и показывать понятным текстом (на русском и английском).
2.4. Память: на iOS работает jetsam. Использовать ключ -mmemuse (или аналогичный механизм ограничения памяти) и считать безопасный бюджет через os_proc_available_memory(). Если пользователь выбрал словарь/потоки, не помещающиеся в бюджет, показать предупреждение и предложить автоснижение. Entitlement com.apple.developer.kernel.increased-memory-limit добавить в entitlements (может быть отброшен при ресайне бесплатным Apple ID, приложение должно нормально работать и без него). Число потоков по умолчанию = число производительных ядер, максимум = ProcessInfo.activeProcessorCount.

== 3. ФУНКЦИИ ПРИЛОЖЕНИЯ ==
3.1. Создание архива («Add to Archive») — экран, повторяющий десктопный диалог 7-Zip, со ВСЕМИ полями:
  - имя архива и папка назначения;
  - формат: 7z, zip, tar, gzip, bzip2, xz, wim (для тех, что поддерживают запись);
  - уровень сжатия: Store, Fastest, Fast, Normal, Maximum, Ultra (0,1,3,5,7,9);
  - метод (зависит от формата: LZMA2, LZMA, PPMd, BZip2, Deflate, Deflate64, Copy, zip: Deflate/BZip2/LZMA/PPMd);
  - размер словаря, word size, solid block size (Non-solid, 1 МБ … 4 ГБ, Solid, как в 7-Zip), число потоков, лимит памяти (в процентах/МБ, как у 7-Zip), отображение расчётной памяти для сжатия и распаковки; списки значений зависят от формата, метода и уровня, как в десктопной версии;
  - split to volumes (размер тома: 10M, 100M, 650M, 700M, 1G, 4480M и пользовательский ввод);
  - Update mode (Add and replace / Update and add / Freshen / Synchronize), Path mode (Relative / Full / Absolute);
  - опции: Delete files after compression, Compress shared files — не показывать, Create SFX — не показывать (не работает на iOS); дополнительно: сохранять временные метки, симлинки, исключать по маске (-x), включать по маске, рекурсия;
  - шифрование: пароль (поле + переключатель Show Password + подтверждение), метод AES-256, чекбокс «Encrypt file names» (-mhe=on, только для 7z);
  - поле «Parameters» для произвольных ключей 7-Zip (-m... и т.д.);
  - кнопка сохранения/загрузки пресетов настроек, пресеты по умолчанию: «Быстро», «Обычный», «Максимум», «Максимум + шифрование».
  Диалог формирует командную строку для sz_run; в режиме разработчика показывать итоговую команду.
3.2. Просмотр архива: открыть архив, показать дерево папок и файлов (имя, размер, упакованный размер, дата, CRC, метод, атрибуты, зашифрован ли), поиск и сортировка, выбор нескольких элементов. Информация об архиве (команда l -slt / i): формат, метод, solid, размер заголовков, физический размер и т.д.
3.3. Распаковка: всё / выбранное, куда (папка из Files или песочница приложения), режимы путей (с полными путями / без путей), политика перезаписи (спрашивать, перезаписать, пропустить, переименовать), пароль с запоминанием на сессию, многотомные архивы (.7z.001, .part1.rar и т.д. — открывать по первому тому, подтягивать соседние).
3.4. Проверка архива (test), удаление файлов из архива (d), добавление файлов в существующий архив (u/a), переименование внутри архива (если поддерживается), хэши файлов (CRC32, CRC64, SHA-1, SHA-256, SHA-512, BLAKE2sp, XXH64) через команду h, бенчмарк (b) с красивым отображением результата.
3.5. Предпросмотр файла из архива (Quick Look): распаковать во временную папку, показать, потом очистить. Поделиться файлом (Share Sheet).
3.6. Интеграция с iOS:
  - регистрация типов документов (7z, zip, rar, tar, gz, tgz, bz2, xz, iso, cab, wim и т.д.): «Открыть в…» из Файлов, Safari, Telegram и других приложений;
  - UIDocumentPicker для выбора файлов/папок (импорт в режиме открытия на месте, без копирования больших файлов), корректная работа с security-scoped URL (startAccessing/stopAccessing) и bookmark’ами для папок назначения;
  - Info.plist: UIFileSharingEnabled = YES, LSSupportsOpeningDocumentsInPlace = YES, чтобы папка приложения была видна в «Файлы»;
  - Share Extension и прочие расширения НЕ делать: у бесплатного Apple ID лимит на число App ID, расширения его съедают;
  - выполнение операций в фоне: UIApplication.beginBackgroundTask, отключение автоблокировки экрана на время операции, локальное уведомление по завершению; при уходе в фон не терять прогресс;
  - очередь задач: несколько операций, статус каждой, отмена, повтор, журнал/лог операции (с копированием в буфер).
3.7. Настройки приложения: язык (RU/EN, строки в Localizable.strings), папка по умолчанию, поведение при перезаписи, пресет сжатия по умолчанию, лимит памяти по умолчанию, авто-очистка временных файлов, показ скрытых файлов, формат отображения размеров, хаптики, режим разработчика, «О приложении» (версия, лицензия 7-Zip LGPL + оговорка unRAR, ссылка на исходники).
